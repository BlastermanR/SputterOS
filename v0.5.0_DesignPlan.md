## 1. Release Goal

After v0.5.0, a MicroManipulator firmware author can:

```cpp
class ServoTask : public SputterOS::ICrunchTask {
public:
    SputterMicros crunchPeriodUs()  const override { return 163; }
    SputterMicros maxIterationUs()  const override { return 200; }

    void crunch(SputterMicros now) override {
        auto targets = m_targetBuffer.read();           // AtomicDoubleBuffer
        for (int j = 0; j < 3; j++) updateJoint(j);    // blocking SPI OK
        m_encoderBuffer.write(currentState());
    }

    void onCrunchAbort() override {
        for (int j = 0; j < 3; j++) m_motors[j].disable();
    }
};

// Registration:
builder.core(1).setCrunchTask(&servo);
builder.core(0).addScheduledTask(&motionPlanner);
builder.addBackgroundTask(&logger);
BuildResult r = builder.build();
// Core 0: flat-loop (ControlTask + motionPlanner + background dispatcher)
// Core 1: tight crunch loop (servo only, watchdog + safety abort)
```

**Key capabilities delivered:**
- `ICrunchTask` interface for exclusive-core, blocking-tolerant, sub-ms loops
- `CrunchDispatcher` with overrun detection, watchdog kick, and safety abort
- `AtomicDoubleBuffer<T>` for wait-free latest-value cross-core data sharing
- `s_safetyAbort` atomic wired from `ControlTask` → `CrunchDispatcher`
- Background task dispatch separated from the scheduled task loop (resolves Phase 3 TODO)
- Retired interface shims (`IAsyncTask`, `ICriticalTask`) removed
- Stdlib trivial headers (`<algorithm>`, `<cctype>`, `<cassert>`) eliminated

## 2. Non-Goals

| Item | Why deferred |
|------|------|
| `DeadlineTracker` wired into FLAT_LOOP dispatch | Touches the hot path for all existing users; defer to v0.6 |
| Period-aware skip logic (LTP §2.2) | Philosophical shift from task autonomy; defer to v0.6 |
| Priority-ordered dispatch (LTP §2.3) | Requires §2.2 first; defer to v0.6 |
| Cache-safe `AtomicDoubleBuffer` (seqlock variant) | No cached platform target; `CachePolicy` template parameter provides a zero-cost extension point — user supplies flush/invalidate for cached MCUs without API break |
| Codebase-wide atomic/sync abstraction layer | `std::atomic` is freestanding C++17 (available on all targets); wrapping 11 kernel atomics adds risk with zero payoff; mutex fallback would violate lock-free, ISR-safe kernel invariants |
| Stdlib Phase 2+ elimination | Scope creep; Phase 1 trivial replacements only |
| Freestanding build mode | Depends on Phase 2 stdlib work |
| Cross-compilation CI | No ARM target yet |
| Configurable `TaskTimer` bucket width | Nice-to-have; not needed when crunch core bypasses `TaskTimer` |
| `DeadlineTracker` integration into `CrunchDispatcher` | Tier C scope; can be added in a point release |

## 3. Work Packages

### WP-1: Background Dispatcher

**Source:** LTP §2.1 | **Effort:** M | **Risk:** ● | **Prerequisites:** None

Resolves the long-standing Phase 3 TODO: `BackgroundDiagnosticsTask` is currently double-registered in the core task list *and* the background ring. This WP separates background dispatch from the scheduled task loop.

#### Design

Modify `System<Cfg>::tick()` to dispatch background tasks after the scheduled task loop, budget-gated by remaining gap time:

```cpp
static void tick(std::size_t coreId, SputterMicros systemTimeMicros)
{
    // --- existing: rollover detection, utilization start ---

    // Phase 1: Scheduled tasks (unchanged)
    SputterMicros busyAccum = 0;
    for (std::size_t t = 0; t < s_cores[coreId].taskCount; ++t)
    {
        ITask *tsk = s_cores[coreId].tasks[t];
        if (tsk)
        {
            tsk->timer().start();
            tsk->tick(systemTimeMicros);
            tsk->timer().stop();
            busyAccum += tsk->timer().lastDuration();
        }
    }

    // Phase 2: Background tasks — round-robin, budget-capped
    if (coreId == s_backgroundCoreId)  // only the designated core dispatches background
    {
        SputterMicros gapBudget = CfgControlBudgetUs<Cfg>::value;
        SputterMicros used      = busyAccum;

        for (std::size_t i = 0; i < s_backgroundTaskCount && used < gapBudget; ++i)
        {
            IBackgroundTask *bg = s_backgroundTasks[s_bgRoundRobin];
            s_bgRoundRobin      = (s_bgRoundRobin + 1) % s_backgroundTaskCount;

            if (bg)
            {
                SputterMicros taskBudget = bg->maxBudgetUs();
                if (used + taskBudget > gapBudget)
                    break;

                bg->timer().start();
                bg->tick(systemTimeMicros);
                bg->timer().stop();
                used += bg->timer().lastDuration();
            }
        }
    }

    // --- existing: utilization end, queue monitor, scheduler health ---
}
```

#### Changes Required

| File | Change |
|------|--------|
| `System.h` | Add `s_bgRoundRobin`, `s_backgroundCoreId` inline statics. Modify `tick()` to add Phase 2 background dispatch. |
| `SystemBuilder.h` | Remove `BackgroundDiagnosticsTask` from core task list prepend. Keep it in `s_backgroundTasks` ring only. Set `s_backgroundCoreId` (default: last active core, or Core 0 in single-core). |
| `BackgroundDiagnosticsTask.h/cpp` | No change — it already inherits `IBackgroundTask` and lives in the background ring. Just stop also adding it to a core's task list. |

#### Tests

- **New unit test:** `test_BackgroundDispatcher.cpp` — verify round-robin order, budget cap, gap exhaustion
- **Modified:** `test_SystemBuilder.cpp` — verify `BackgroundDiagnosticsTask` is no longer in core task list
- **Modified:** `test_DiagnosticsTask.cpp` — verify tick still fires via background dispatch path
- **System test:** `test_DiagnosticsMonitoring.cpp` — verify diagnostics still report in full pipeline

class ICrunchTask : public ITask {
public:
    virtual ~ICrunchTask() = default;

    ICrunchTask(const ICrunchTask &)            = delete;
    ICrunchTask &operator=(const ICrunchTask &) = delete;

    bool isCrunchTask() const final { return true; }
    bool isScheduled()  const final { return false; }
    bool isBackground() const final { return false; }

protected:
    ICrunchTask() = default;
};

```cpp
static void run(std::size_t coreId)
{
    s_sync.setInit(coreId);
    if (!s_coreInitialized[coreId]) { init(coreId); }
    s_sync.startupBarrier(/* ... */);

    auto &core = s_cores[coreId];

    if (core.mode == CoreDispatchMode::CRUNCH && core.crunchTask)
    {
        // Delegate to CrunchDispatcher (WP-3)
        s_crunchDispatcher.runLoop(coreId);
    }
    else
    {
        // Existing flat-loop dispatch
        while (isActiveState(s_kernelState) && !anyStopConditionFired())
        {
            tick(coreId, s_timer.nowMicros());
        }
    }

    // Shutdown sequence (unchanged)
    if (coreId == 0) transitionTo(KernelState::SHUTTING_DOWN);
    s_sync.shutdownBarrier(/* ... */);
    if (coreId == 0) transitionTo(KernelState::SHUTDOWN);
}
```

#### Build-Time Validation (in `SystemBuilder::build()`)

1. A `CRUNCH` core may have exactly one `ICrunchTask` and zero other tasks.
2. `ICrunchTask` cannot be registered on Core 0 (Core 0 must remain FLAT_LOOP for safety).
3. `kCoreCount >= 2` when any core is `CRUNCH` mode.
4. `crunchPeriodUs() >= CfgMinSchedulePeriodUs` (same floor as `IScheduledTask`).
5. Warn (not error) if `maxIterationUs() > 500` µs.

### WP-3: CrunchDispatcher

**Source:** Priority Task Changes §6 | **Effort:** M | **Risk:** ◑ | **Prerequisites:** WP-2, WP-5

The core runtime for `CRUNCH`-mode cores. Manages the tight loop with watchdog, overrun detection, and safety abort.

#### New File

**`include/sputteros/kernel/CrunchDispatcher.h`**

```cpp
template <typename Cfg>
class CrunchDispatcher {
public:
    void configure(ICrunchTask *task, WatchdogKickFn watchdogKick);

    void runLoop(std::size_t coreId)
    {
        using S = System<Cfg>;

        while (S::isActiveState(S::kernelState()) && !S::anyStopConditionFired())
        {
            // 1. Safety abort check (sub-nanosecond atomic read)
            if (S::isSafetyAborted())
            {
                m_task->onCrunchAbort();
                S::errorLogger().log(ErrorCode::SOFT_ABORT,
                    S::timer().nowMicros(), 0.0f);
                return;
            }

            // 2. Watchdog kick
            SputterMicros now = S::timer().nowMicros();
            S::watchdog().kick(coreId, now);
            if (m_watchdogKick) m_watchdogKick();

            // 3. Dispatch crunch iteration with timing
            SputterMicros start = S::timer().nowMicros();
            m_task->crunch(now);
            SputterMicros elapsed = S::timer().nowMicros() - start;

            // 4. Overrun detection
            if (elapsed > m_task->maxIterationUs())
            {
                ++m_overrunCount;
                S::errorLogger().log(ErrorCode::CRUNCH_OVERRUN,
                    now, static_cast<float>(elapsed));

                if (m_overrunCount >= CfgCrunchMaxOverruns<Cfg>::value)
                {
                    m_task->onCrunchAbort();
                    S::errorLogger().log(ErrorCode::HARD_FAULT,
                        now, static_cast<float>(m_overrunCount));
                    return;
                }
            }
            else
            {
                m_overrunCount = 0;  // Reset consecutive counter on clean iteration
            }
        }
    }

    uint32_t overrunCount() const { return m_totalOverruns; }

private:
    ICrunchTask   *m_task{nullptr};
    WatchdogKickFn m_watchdogKick{nullptr};
    uint32_t       m_overrunCount{0};
    uint32_t       m_totalOverruns{0};
};
```

#### ErrorCode Addition

Add `CRUNCH_OVERRUN` to `ErrorLogger::ErrorCode` enum:

```cpp

    CRUNCH_OVERRUN,   ///< Crunch task iteration exceeded maxIterationUs().
};
```

### WP-4: AtomicDoubleBuffer

**Source:** Priority Task Changes §8 | **Effort:** S | **Risk:** ◑ | **Prerequisites:** None (independent)

Wait-free latest-value cross-core data sharing. Replaces ad-hoc `std::atomic` wrappers for multi-word structs.

#### New File

**`include/sputteros/osal/sync/AtomicDoubleBuffer.h`**

```cpp
/// @brief No-op cache policy for platforms without data cache (RP2040, RP2350).
struct NoCachePolicy {
    static void flushBuffer(const void*, std::size_t)      {}
    static void invalidateBuffer(const void*, std::size_t) {}
};

/// @tparam T          Value type (trivially copyable, ≤ 64 bytes recommended).
/// @tparam CachePolicy  Cache maintenance policy. Default `NoCachePolicy` for
///                       cache-less targets. Override with platform-specific
///                       flush/invalidate for cached dual-core MCUs (e.g. STM32H7).
template <typename T, typename CachePolicy = NoCachePolicy>
class AtomicDoubleBuffer {
public:
    AtomicDoubleBuffer() = default;

    AtomicDoubleBuffer(const AtomicDoubleBuffer &)            = delete;
    AtomicDoubleBuffer &operator=(const AtomicDoubleBuffer &) = delete;

    /// Writer side — wait-free, never blocks.
    void write(const T &value)
    {
        std::size_t next = m_writeIndex.load(std::memory_order_relaxed) ^ 1;
        m_buffers[next] = value;
        CachePolicy::flushBuffer(&m_buffers[next], sizeof(T));
        m_writeIndex.store(next, std::memory_order_release);
    }

    /// Reader side — wait-free, returns latest complete value.
    T read() const
    {
        std::size_t idx = m_writeIndex.load(std::memory_order_acquire);
        CachePolicy::invalidateBuffer(&m_buffers[idx], sizeof(T));
        return m_buffers[idx];
    }

private:
    T m_buffers[2]{};
    std::atomic<std::size_t> m_writeIndex{0};
};
```

#### Cache Policy Design

`AtomicDoubleBuffer` is parameterized on a `CachePolicy` type (default: `NoCachePolicy`). This is a zero-cost compile-time extension point — on cache-less platforms the flush/invalidate calls are empty inlines that the compiler eliminates entirely.

**Rationale for this approach over a codebase-wide atomic wrapper:**

| Consideration | Assessment |
|---------------|------------|
| `std::atomic` availability | `<atomic>` is freestanding in C++17 — every target that compiles SputterOS already has it. No fallback needed. |
| Existing kernel atomics | 11 `std::atomic` variables across 5 kernel files use scalar types (`bool`, `size_t`, `int64_t`) that are natively atomic on all ARM/x86 targets. Wrapping them adds risk with zero benefit. |
| Mutex fallback | Would violate zero-heap, lock-free, ISR-safe kernel invariants. `IMutex` is already deprecated for cross-core data. |
| Multi-word cache coherency | The *only* cross-core non-atomic data transfer in SputterOS is `AtomicDoubleBuffer<T>`. This is the one place cache maintenance matters, and a policy template handles it at compile time without polluting the rest of the codebase. |
| LTP §1.3 conclusion | *"Do not replace `<atomic>`. It is freestanding-compatible in C++17, works on bare-metal ARM Cortex-M, and carries zero runtime overhead."* |

**Platform examples:**

```cpp
// RP2350 (no data cache): use default — zero overhead
AtomicDoubleBuffer<JointTargets> buf;

// STM32H7 (Cortex-M7 with D-cache): user supplies cache ops
struct STM32H7CachePolicy {
    static void flushBuffer(const void* p, std::size_t n) {
        SCB_CleanDCache_by_Addr(const_cast<void*>(p), n);
    }
    static void invalidateBuffer(const void* p, std::size_t n) {
        SCB_InvalidateDCache_by_Addr(const_cast<void*>(p), n);
    }
};
AtomicDoubleBuffer<JointTargets, STM32H7CachePolicy> buf;
```

The cache policy is a HAL-level concern injected by the user project — the kernel itself never provides cache implementations.

#### Scope

- **Default `NoCachePolicy`** for v0.5.0 — targets RP2350 (no data cache, shared SRAM).
- **`CachePolicy` template parameter** designed now so cached-platform support requires no API break — just a user-supplied policy type.
- Seqlock variant remains deferred (non-goal for v0.5.0).

#### Tests

- **New unit test:** `test_AtomicDoubleBuffer.cpp`
  - Single-threaded write/read round-trip
  - Latest-value semantics (overwrite, not queue)
  - Zero-initialized default state
  - Multi-word struct integrity (24-byte and 48-byte structs)
  - Custom `CachePolicy` — verify flush/invalidate called at correct points

### WP-5: Safety Abort Bridge

**Source:** Priority Task Changes §11 | **Effort:** S | **Risk:** ◑ | **Prerequisites:** WP-2

Adds a global atomic abort flag to `System<Cfg>` wired from `ControlTask::evaluateSafety()` to `CrunchDispatcher`.

#### Changes

| File | Change |
|------|--------|
| `System.h` | Add `inline static std::atomic<bool> s_safetyAbort{false}`. Add `signalSafetyAbort()`, `isSafetyAborted()`, `clearSafetyAbort()` static methods. Reset in `reset()`. |
| `ScheduledControlTask.h` | In `evaluateSafety()`, after `m_app->forceSafeAbort()`, call `System<Cfg>::signalSafetyAbort()`. |

#### Safety Model

```
Core 0: ControlTask::evaluateSafety()
   └─ ISafetyMonitor::isSafe() fails
       └─ m_app->forceSafeAbort()
       └─ System<Cfg>::signalSafetyAbort()                     ← release store

Core 1: CrunchDispatcher::runLoop()  (every iteration)
   └─ System<Cfg>::isSafetyAborted()                           ← acquire load
       └─ m_task->onCrunchAbort()
       └─ return
```

**Worst-case latency:** ~163 µs (one crunch iteration in-flight when abort fires).

This is orthogonal to Tier 0 hardware ISR safety (`executeFastFault()`), which can disable PWM via GPIO ISR in sub-microsecond time. The abort bridge is the kernel-level software path.

#### Tests

- **New unit test:** `test_SafetyAbortBridge.cpp` — signal/check/clear, reset clears flag
- **Modified:** `test_ControlTask.cpp` — verify `signalSafetyAbort` called on safety failure
- **New system test (in `test_CrunchPipeline.cpp`):** — cross-core abort propagation

#### `SimulatedServoTask`

```cpp
class SimulatedServoTask : public SputterOS::ICrunchTask {
public:
    SputterMicros crunchPeriodUs()  const override { return 163; }
    SputterMicros maxIterationUs()  const override { return 200; }

    void init() override {}
    void tick(SputterMicros) override {}  // unused — crunch() is the entry point

    void crunch(SputterMicros now) override {
        auto targets = m_targetBuffer.read();
        m_iterationCount++;
        // Simulate ~30 µs of blocking SPI per joint × 3 joints
        volatile uint32_t sink = 0;
        for (uint32_t i = 0; i < 900; i++) sink += i;
        m_stateBuffer.write({m_iterationCount, now});
    }

    void onCrunchAbort() override { m_aborted = true; }

    AtomicDoubleBuffer<TargetState>  m_targetBuffer;
    AtomicDoubleBuffer<EncoderState> m_stateBuffer;
    uint32_t m_iterationCount{0};
    bool     m_aborted{false};
};
```

Registered with CTest; validates dual-core CRUNCH lifecycle on host.

## 9. Migration & Backward Compatibility

### Breaking Changes

| Change | Impact | Migration |
|--------|--------|-----------|
| `IAsyncTask` removed | Any code inheriting `IAsyncTask` | Change base class to `IBackgroundTask` (identical API) |
| `ICriticalTask` removed | Any code inheriting `ICriticalTask` | Change base class to `IScheduledTask` |
| `BackgroundDiagnosticsTask` no longer in core task list | Code that expects it in `s_cores[N].tasks[]` | Access via `System<Cfg>::backgroundTasks()` instead |
| `ITask` gains `isCrunchTask()` | Virtual table size increases by one entry | No user action needed; ABI change for derived classes |

### Non-Breaking Additions

- `ICrunchTask`, `CoreDispatchMode`, `CrunchDispatcher`, `AtomicDoubleBuffer` — all new, no existing code affected.
- `System::signalSafetyAbort()` / `isSafetyAborted()` — new static methods, no existing behavior change.
- `CRUNCH_OVERRUN` ErrorCode — appended to enum, does not shift existing values.
- `kCrunchMaxOverruns` config field — optional with SFINAE default; existing Cfg structs unchanged.

### Versioning

Bump CMake project version: `0.2.0` → `0.5.0`.

## 10. Acceptance Criteria

- [ ] All existing 535 tests pass with zero regressions.
- [ ] `ICrunchTask` can be registered on Core 1 via `builder.core(1).setCrunchTask()`.
- [ ] `System::run(1)` enters `CrunchDispatcher::runLoop()` on a CRUNCH core.
- [ ] `CrunchDispatcher` kicks watchdog, detects overruns, and aborts after `kCrunchMaxOverruns` consecutive violations.
- [ ] `ControlTask::evaluateSafety()` sets `s_safetyAbort`; `CrunchDispatcher` reads it and calls `onCrunchAbort()` within one iteration.
- [ ] `AtomicDoubleBuffer<T>` round-trips multi-word structs with latest-value semantics.
- [ ] Background tasks dispatch via gap-time budget in `tick()`, not via the core task list.
- [ ] `BackgroundDiagnosticsTask` no longer appears in any core's task array.
- [ ] `build()` rejects `ICrunchTask` on Core 0, multiple tasks on a CRUNCH core, and CRUNCH with `kCoreCount == 1`.
- [ ] `crunchloop` example project builds, runs, and passes CTest.
- [ ] `<algorithm>`, `<cctype>`, `<cassert>` no longer included by kernel headers.
- [ ] `IAsyncTask.h` and `ICriticalTask.h` deleted.
- [ ] `make test` passes on all platforms (MSYS2/MinGW, Linux, macOS).
- [ ] All documentation listed in WP-9 is updated.
- [ ] `make format` reports no changes.
